# Workspace VMs

One doc per VM on g8: what the workspace needs there, beyond the base every VM gets. The doc is the record; the scripts that apply it are in `collielab` (`hosts/<vm>/setup.sh`, base in `hosts/g8/vm-template/provision.sh`, runbook `hosts/g8/README.md`).
Map of machines and addresses: `../home-systems.md`. How the MBP manages machines: `../fleet.md`. T3 against a VM: `../t3-code-remote.md`.

## Adding a workspace VM

1. Survey the workspace on the MBP (tools pinned in `mise.toml`, system packages, docker stacks, Claude config, logins, secret files, Mac-only paths). The prompt used for hookdeck is in `../../work/task-2/log.md` history; its result is `../../work/task-2/hookdeck-vm-requirements.md`.
2. `bin/new-vm <id> <name> <cores> <memory_mb> <disk_gb>` in collielab, then `terraform apply` and commit.
3. Write `collielab/hosts/<name>/setup.sh` for what only this VM needs (no logins, no secrets), run it.
4. Write `vms/<name>.md` from the template below.
5. Alex: logins on the VM, T3 environment on the MBP.
6. Snapshot once it works: `ssh g8 'qm snapshot <id> <name>'`.

## Template for `vms/<name>.md`

```
# <name> VM
Purpose, VM ID, address, size, date built, workspace repo and branch, path on the VM.

## Tools beyond the base        (what, why, which script installs it)
## Logins                        (table: what, command on a headless VM, who uses it, state, how to re-do)
## Secret files                  (paths and purpose only; where the canonical copy lives)
## First run                     (ordered steps from a fresh VM to a working session)
## Running the stack             (how, ports, how to reach it from the MBP)
## Differences from the MBP      (Mac-only paths, things that behave differently on Linux)
## Open points
```

## Rules for every workspace VM

- Logins and secrets are done by Alex or copied on his say-so; scripts never contain them.
- A VM holds only its own workspace's credentials, and never keys to g8 or other machines.
- Every login on a VM is "open this link on the MBP, enter this code": the VM has no browser.
- Its own SSH key for GitHub (`~/.ssh/id_ed25519`, generated by `setup.sh`), registered on GitHub under the VM's name, so it can be revoked alone.
