# task-9: Tailscale for the lab, one address set, home devices through gw
- Asked: same URL, same `ssh hookdeck-ws`, same T3 environment at home and away, no app needed at home (Alex, 2026-10-03; `design.md`).
- Outcome (2026-10-04): "option 2" built and working. Home router static route `100.64.0.0/255.192.0.0` → gw (`192.168.1.110`); gw = Tailscale node + router (forwarding + masquerade, `collielab/hosts/gw/tailnet.sh`, `check.sh`); lab names on Tailscale addresses (gw `100.126.136.120`, Mini `100.91.137.41`, hookdeck-ws `100.113.20.22`); access rules, tags, key expiry and the vm-join client in `collielab/terraform/tailscale.tf`; VMs join opt-in (`bin/new-vm --tailscale`, `bin/vm-tailnet`); Proxmox firewall so VMs can't start connections into the home network (`collielab/hosts/g8/firewall.sh`); HSTS on gw; strict SSH host keys. Explainer and runbooks: `docs/tailscale.md`. Every change + undo: `log.md`.
- Decisions: one address set via gw, not two name sets or a subnet router (same names everywhere); VM tailnet join is opt-in per VM; VMs get no IPv6 (Viettel's home prefix changes, can't be fenced); policy = own devices all, gw → VMs + Mini, VMs nothing; tags and the policy owned by Terraform; gateway logins deferred on purpose; two-factor and guest Wi-Fi skipped for now; g8 not rebooted to test (TASK-14 checklist).
- Learned: a full VPN on a device swallows `100.x` (MBP PIA needed a split-tunnel exception); Debian's `nftables` service flushes every rule incl. Tailscale's (disabled on gw); tagging an already-joined node leaves key expiry on; the ZTE router's DNS passes `100.x` answers and tolerates the one-sided path; Calibre-Web on the Mini returns 500 (existing, unrelated).
