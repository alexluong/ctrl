## Checklist per slice

- [ ] Every supply/demand command versions `availability:<hotel>` in the same batch (D-8 list: assign/change room, dates change, check-in w/ assignment, OOO/return, room retire/type change, overbooking override)
- [ ] Event names `agg.past_verb`, envelope fields per D-12; `schema_version` set; types never renamed
- [ ] `command_id` UNIQUE + duplicate → original result (D-12 clarification); money commands idempotent
- [ ] Tier split honoured (D-22): Booking/Stay/Ledger fold; Room/Setup/Guest/User rows are truth + event appended in same batch
- [ ] No PII in event payloads — ids only (D-20); new sensitive columns on the D-23 denylist
- [ ] Projections written in the same `batch()`; `rebuildProjections` reproduces them (truncate → replay → diff). **Replay never touches `rooms`, `contacts`, `guests`, `users`** (tier b / PII, D-20).
- [ ] **A money command is one batch**: every fact it changes (line, entry, status) lands together; a test asserts the events share a `correlationId`.
- [ ] Any command whose *guard* reads a table another command writes (room serviceable ↔ stay checked in) versions `availability:all` on **both** sides.
- [ ] Reactions (§10) run once inline, not on replay
- [ ] `requireUser()` on every server fn; owner-only commands guarded (from slice 4)
- [ ] `decide` functions unit-tested incl. the reject paths; conflict retry tested
- [ ] D-24: no domain logic in a server fn; every new command is a `Hotel` method with at least one scenario test against `MemoryStore`
- [ ] **A blocked submit must say why on the page** — no silent HTML validation (`step`, `required`, empty selects); `noValidate` + rendered message, or a visible empty state.
- [ ] **Disable a control only for a no-op, never for a rule.** If the domain can refuse it, the click goes through, the domain refuses, the reason renders (`useCommand` + `CommandError`, `src/ui/command.tsx`). Overbooking override must be clickable. Not unit-testable — click every refused path by hand.
- [ ] **Migrations are additive** (expand/contract over two deploys if not) — deploy order is migrate → build → ship.
- [ ] **Migrations apply on a populated DB**, not just an empty one (drizzle-kit `ADD COLUMN NOT NULL` trap). Run against a DB with rows before calling it done.
- [ ] Upcaster: fold path throws on a gap; display paths tolerate and flag.
- [ ] `pnpm check` green; staging deploy loads; flow walkable in a browser
- [ ] product.md amended for any gap dev discovered (not just code)

- **Forms never fall back to GET** — `method="post"` on every form (N11; PII in the URL is PII in the access log). Same for GET search: **PII search terms never in the URL** (N12).

- **Decide inside the thunk** — every read and rule runs inside `plan()`; nothing decided or minted before it (D-8 retry property; caught 2026-09-24).

- **Adapters reject shape only** — business constraints are rule codes; any zod failure still returns `{ok:false, code:"input.invalid"}`, never throws (D-24 b, N15).

- **The screen decides what to send, never whether it is allowed** — no rule re-checked in the UI with its own message (dev, N14; a copied rule drifts), and **no rule answered by the UI on the user's behalf** (no default reason/description filled in to satisfy a `*Required` rule; N16).

- **Access changes end live sessions in the same batch** — deactivate / password reset / role change never leaves a cookie that outlives the row (D-18 built note).

- **A library that re-validates gets our rule, not its default** — username/password/email patterns are one constant shared with Better Auth (N17).
- **Every tier (b) row has a creating event** — no row is written outside `change()` / a commit's `writes`; a history page for any entity is never empty (dev's guest gap, 2026-09-24).

- **What-changed is compared against the row, never against what the form sent** — the screen must send everything (N16), so only the rules can say nothing moved; no `*.updated` event for a no-op (N18).
