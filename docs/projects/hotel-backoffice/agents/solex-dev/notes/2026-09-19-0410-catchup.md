**Questions / tradeoffs to raise with Alex:**
1. **Paid gate:** Cloudflare Containers requires the **Workers Paid plan (~$5/mo)** + per-second container billing. Not on free tier. Is that ok, or does that push us to WASM (free) first? My lean: pay the $5 — Containers is the only path where "just Go" (net/http, database/sql, sqlc, real stdlib) holds; WASM/TinyGo fights every library.
2. **Containers vs WASM, deeper:** Containers = cold start seconds-ish (image pull + boot), sleep-after-idle, Worker in front handles routing/DO addressing; storage = Hyperdrive→PG or Worker-side D1 via RPC. WASM = ms cold starts, native D1/KV/DO bindings, but TinyGo stdlib gaps (reflection, `database/sql`, encoding/json quirks), 10MB bundle cap. For a low-traffic hotel back office cold start matters less than dev ergonomics → Containers.
3. **Storage:** D1 (SQLite, Worker-native, free, only reachable from Worker → Go in container needs an RPC hop or Worker-side data access) vs **Hyperdrive→Neon** (real PG, `pgx` from Go, Neon free tier has cold-start of its own ~500ms after idle). Also consider **Durable Objects** later for per-aggregate ES streams. Spike: Hyperdrive→Neon. Need Alex's ok to create a Neon account/project (free) and whether Neon vs Supabase.
4. **"Done" definition:** propose = a public URL returning JSON from a PG query; `just fix` / `just check`; a table in stack.md with cold vs warm p50 numbers from ~20 `curl -w` samples; a written recommendation. Not done = auth, migrations framework, CI. Should CI (GH Actions deploy) be in spike scope? Lean no.
