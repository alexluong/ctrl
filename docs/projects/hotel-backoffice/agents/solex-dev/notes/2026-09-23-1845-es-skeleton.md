# ES skeleton built

**Doing:** Alex asked to see event-driven architecture working, browse events, and have a system-admin tool for the DB. Built and deployed all three.

**Scope note:** architect's message said stand by until D-8 accepted + product v1. Alex asked directly, so I built. Told architect after, not before — Alex outranks the standby.

**Decisions I made while building:**
- **No Durable Object.** `UNIQUE(stream_id, version)` + retry gives the same serialisation as a single-writer DO, without putting Cloudflare back into the dev loop. This is D-8 as proposed; building it confirmed the reasoning holds.
- **Projections in the same batch as the event.** Proven atomic by a test that makes a projection fail and asserts the event didn't land.
- **D-9 folded in immediately** rather than later. Adding `hotelId` to streams + projections cost ~30 minutes today; retrofitting it across aggregates and a populated log would have cost a day.
- **Console is a system tool, not an admin persona screen** (Alex corrected me on this mid-build). So: raw log, raw tables, replay button — the things an operator wants, not what an owner wants.
- **Console fails closed when deployed**, open locally. A missing secret must never mean open. Token compared in constant time.
- **Room as the first aggregate** rather than Booking: small enough to finish, real enough to exercise rules (housekeeping blocked while out of order), and it maps to the board the client actually stares at.

**Bugs I made and caught:**
- `event.currentTarget` read after an await → null. Classic; caught by the browser test, not by types.
- Put the stream-id helper next to the tenant lookup, which reads secrets, so importing it from the aggregate dragged `cloudflare:workers` into the client bundle. Aggregates are shared with the browser and must stay pure. Deploy caught it.
- Loader kept fetching while the layout showed the sign-in form → 500 in the browser for a routine state. Reads now return a refusal shape.

**Wasted time on:** my own Playwright assertions, twice — asserting on `networkidle` before the route swapped its view, and a stale sed that never applied. Both looked like app bugs and weren't. Also left ~10 orphaned chromium processes that starved the machine and made later runs hang. Kill browsers on failure paths.

**Next:** Booking is the real test of the store, because availability is the cross-aggregate rule. Before that, worth agreeing: auth (staging is public), and event payload versioning.
