## Alex's two challenges, and the honest answers

**"did you just build the system flow? just manual ui & table build?"** — Yes, ~350 lines hand-written. Fair challenge, and the honest split is:
- The **generic table browser duplicates Drizzle Studio**, which is already wired as `pnpm db:studio`. That part is arguably redundant; offered to drop it.
- The **event log view, stream/type filtering, and replay button** are not redundant — no generic DB tool knows what an event stream is, or that a projection can be dropped and recomputed.
- If it grows: the answer is probably *fewer* bespoke screens, not more. Table browsing → Studio. Keep the ES-specific views.

**"mixed english & vietnamese which is not ideal"** — He was right and I was wrong. I had deliberately left the console English ("operator tool, code's vocabulary"), but the shell (nav, language picker) follows the locale, so a console page rendered half and half. A principle that produces a visibly sloppy page is a bad principle. Now everything follows the picker; only identifiers stay literal (table names, stream ids, column names, event payload JSON).

## Learnings worth keeping

- **Design principles have to survive being looked at.** "Console stays English" sounded principled in prose and looked broken on screen. Check decisions against the rendered page, not the reasoning.
- **Server-resolved locale is non-negotiable with SSR.** Choosing in the browser guarantees a hydration mismatch. Same root cause as the earlier `toLocaleString()` bug — anything environment-dependent must be decided server-side and handed down.
- **`getRequestHeader()` does not always return a string.** Coerce.
- **TanStack Start's import protection is a real boundary.** A route importing a helper that reads the request drags server-only code into the client bundle and fails the Workers build. Route server-only work through `createServerFn` and keep the helper unexported. Two builds broke on this; both times the fix was "cross the boundary explicitly".
- **Typed dictionaries are worth it**: `vi: Messages` keyed off `typeof en` means a missing key is a build error. Caught several during the console pass.
- **Playwright assertions lie more often than the app does.** Three "bugs" this session were my test's wait strategy (`networkidle` fires before TanStack swaps the view — wait for content, not the network). Also: kill browsers on failure paths, orphans starve the machine and later runs hang.
